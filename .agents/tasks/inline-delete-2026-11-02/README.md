# Видалення категорій і витрат у списках

Стан: `completed` (локальна реалізація; runtime не перевірено). Дата: 2026-11-02.

## Результат і критерії

Mini App показує видалення поряд із редагуванням у рядках категорій та
витрат, включно з оглядом. Видалення витрати прибране з нижньої частини
редактора. Категорії не мають кнопок архівації/відновлення. Бот пропонує
видалення безпосередньо біля запису в списках; обидва канали запитують
підтвердження та викликають спільний backend із ownership/version checks.

## Scope і рішення

Додати DELETE категорії: фізично видаляти лише без пов'язаних витрат і
активних чернеток; зрозуміло пояснювати `category_in_use` в обох каналах.
Не видаляти витрати каскадом, не змінювати схему БД і старі archive API поля.
Старі archive callbacks відхиляти як застарілі. Зберегти попередні локальні
зміни бібліотеки іконок. Без коміту, deployment чи зміни реальних даних.

## Результат

Видалення доступне в рядку в обох каналах; архівації у UI немає. Після
останнього видалення Mini App показує empty state каталогу; бот пагінує
категорії по 20. Пов'язані витрати/активні чернетки захищено від каскаду.
Наступна дія — runtime перевірки лише за окремим запитом.
