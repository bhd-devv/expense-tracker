# Накопичувальні рахунки

Стан: `completed_local`. Дата: 2026-11-02.

## Результат і критерії приймання

Окремі від категорій накопичувальні рахунки, доступні з головної Mini App
та reply-меню бота. Назва, залишок, історія поповнень і списань
із сумою, датою та необов'язковою нотаткою в обох каналах. Backend перевіряє
власника, точність грошей, залишок та повтор операції.

## Scope / non-goals

Backend/EF migration, OpenAPI й generated consumers, Mini App, aiogram,
правила та ADR. Без переказів, конвертації, прив'язки звичайних витрат
до рахунків, редагування/видалення рахунків або їхніх операцій.

## Рішення й ризики

Нова вимога користувача розширює модель без фінансових рахунків.
Окремий журнал, валюта-позначення з профілю, початковий залишок нуль. Списання понад
залишок відхиляється. Advisory lock власника захищає конкурентні списання;
request ID зберігається разом із результатом. Additive migration потребує
окремого release-кроку; наявні витрати не змінюються.

## Виконання й перевірки

Runtime перевірки за локальними правилами — лише за явним запитом.
Поточний запит стосується реалізації; build/tests/browser/міграція не запускалися.

`openapi-typescript` і `datamodel-codegen` оновили consumers зі збереженої
OpenAPI. Export із живого backend і drift не перевірені. Форматування
Prettier/Ruff виконано. `python3 scripts/check_docs.py --check` і
`git diff --check` пройшли; докази — `output/savings-accounts/`.
