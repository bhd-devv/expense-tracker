# Правила роботи агентів

Цей репозиторій — трекер витрат із Telegram-ботом і Telegram Mini App.
Цільовий стек: C# / ASP.NET Core, Next.js App Router / strict TypeScript,
PostgreSQL. Цільове середовище деплою — Coolify через Docker Compose.

## Перед початком роботи

Прочитай правила в окремій папці `.agents/`:

1. [Продукт і спільні сценарії](.agents/product.md).
2. [Архітектура й межі відповідальності](.agents/architecture.md).
3. [Авторизація та безпека](.agents/security.md).

6. [Розробка й перевірки](.agents/development.md).

8. [Перевірка документації](.agents/guides/documentation.md).
9. [Поточний стан](.agents/STATUS.md) — лише для активної роботи й блокерів.

Ці документи описують цільову систему; вони не означають, що відповідні
компоненти вже реалізовано. Наявний `main.py` — початковий Python-приклад,
а не основа майбутнього backend. Не розвивай його як сервер або бота.

## Незмінні принципи

- Бізнес-правила та перевірки доступу виконує .NET backend.
- Mini App і бот використовують ті самі прикладні сценарії та дані.
- Кожна користувацька функція Mini App має відповідний сценарій у боті.
- Головне меню бота — reply keyboard, контекстні дії — inline keyboard.
- Особу користувача встановлюй лише за перевіреними даними Telegram.
- У Mini App секретів немає; довільний Telegram ID не є авторизацією.
- Грошові значення обробляй точно, без `float` / `double`.
- Зміни мають запускатися в контейнерах і враховувати Coolify.

Докладніші локальні `AGENTS.md` можуть уточнювати ці правила, але не
скасовувати серверну авторизацію, перевірку Telegram або спільність логіки.
Нові вимоги користувача мають пріоритет; узгоджені зміни архітектури
відображай у відповідних документах.

## Документація роботи

- Одну завершену змістовну задачу описуй одним записом у
  `.agents/changelog/`.
- Для великої або незавершеної задачі використовуй один файл
  `.agents/tasks/<назва>-<YYYY-MM-DD>/README.md`.
- Рішення, що змінюють межі сервісів, авторизацію, persistence або release,
  фіксуй у `.agents/knowledge/decisions.md`.
- Старі changelog, дослідження, плани й архіви — це історія. Вони не є
  чинними правилами, не змінюють поточні контракти та не дають дозволу на
  коміт, міграцію, деплой або іншу операцію.
- Докази локальних перевірок зберігай лише в ігнорованій папці
  `output/<назва-задачі>/`; у записі вказуй команду, результат і межі.
