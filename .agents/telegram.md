# Telegram-бот і Mini App UX

## Кнопки й навігація

Основне меню — постійна `ReplyKeyboardMarkup` у приватному чаті:

```text
➕ Додати витрату       📋 Витрати
📊 Звіти               🗂 Категорії
💳 Рахунки             ⚙️ Налаштування
📱 Відкрити застосунок
```

Для головної keyboard використовуй `resize_keyboard` і підтримуваний
Telegram параметр persistence. Кнопка застосунку — `web_app` із HTTPS URL
Mini App. Також можна налаштувати menu button бота для відкриття застосунку.

Усі контекстні дії — `InlineKeyboardMarkup`: вибір категорії, рахунку,
періоду, пагінація, зміна, видалення, підтвердження, «Назад», «Скасувати».
Не замінюй ними головну reply keyboard і не засмічуй головне меню списком
категорій або записів. Текст команди `/start` також повертає головне меню.

## Додавання витрати

1. «Додати витрату» створює серверну чернетку.
2. Користувач вводить суму; сервер нормалізує десятковий роздільник і
   перевіряє точність. Не вгадуй неоднозначні роздільники тисяч.
3. Inline кнопками вибирає рахунок та категорію. Якщо рахунок один,
   допускається автоматичний вибір із відображенням у підтвердженні.
4. Вибирає дату, додає або пропускає нотатку.
5. Бачить підсумок із кнопками «Зберегти», «Змінити», «Скасувати».
6. «Зберегти» викликає спільний backend-сценарій один раз на чернетку.
   Бот показує збережену витрату з діями редагування й повернення до списку.

Початковий onboarding створює налаштування користувача й допомагає додати
рахунок/категорії; не створюй кожного разу дублікати стандартних категорій.
Перший вхід із бота та Mini App має приводити до того самого стану onboarding.

## Стан діалогів і callback

- Зберігай conversation state у PostgreSQL: User, private chat, сценарій,
  поточний крок, чернетка, версія й строк дії. Не тримай його лише в RAM.
- Початковий TTL неактивної чернетки — 30 хвилин. Після завершення поясни,
  що діалог завершено, і запропонуй почати знову; нічого не зберігай автоматично.
- Серіалізуй зміни одного діалогу або використовуй optimistic concurrency.
  Враховуй повторні й несвоєчасні updates, зокрема коли користувач швидко
  натискає кнопки чи паралельно редагує витрату в Mini App.
- `callback_data` — до 64 байтів UTF-8. Використовуй коротку дію та opaque
  серверний ID; не вкладай JSON чернетки, секрети або довірений user ID.
- Callback перевіряє власника, діалог, TTL, очікуваний крок і версію.
  Старі кнопки повертають зрозуміле повідомлення, а не повторюють мутацію.
- Швидко викликай `answerCallbackQuery`, щоб зняти індикатор очікування.
  Повільна робота виконується після надійного прийняття події.
- Для видалення показуй конкретну витрату та окреме підтвердження.
  Після завершення прибирай або оновлюй застарілі inline actions.
- `/cancel` і кнопка «Скасувати» завершують поточну чернетку без фінансової
  мутації. Вихід у головне меню має явну, послідовну поведінку щодо чернетки.
- Екрануй користувацький текст для Telegram HTML/MarkdownV2. Дотримуйся
  обмежень повідомлень і використовуй пагінацію довгих списків.

## Приймання updates

Після перевірки webhook атомарно запиши update у durable inbox з унікальним
`update_id`, після чого поверни 2xx. Worker обробляє inbox і фіксує результат.
При неможливості надійного запису поверни non-2xx, щоб Telegram міг повторити
доставку. Повтор уже прийнятого update повертає 2xx без повторного ефекту.

Власне фінансова мутація має окремий idempotency key чернетки, бо два
натискання однієї кнопки можуть мати різні `update_id`. Обробка inbox,
зміна стану та outbox повідомлення мають узгоджену транзакційну межу.
Враховуй rate limits Telegram, `retry_after`, недоступність API та блокування
бота користувачем. Не скасовуй збережену витрату через помилку повідомлення.

## Mini App

Інтегруй Telegram SDK у client boundary, підтримай `ready`, тему,
safe area/viewport і Telegram BackButton там, де це відповідає навігації.
Loading, auth failure, порожні списки, втрата зв'язку й помилки валідації
мають окремі зрозумілі стани. Після зміни через будь-який канал перечитуй
актуальні дані; realtime інфраструктура для MVP не обов'язкова.

Основні дії доступні з клавіатури й мають підписи для screen readers.
Під час невідомого результату збереження не показуй хибне «не збережено»
і не створюй нову операцію автоматично.
