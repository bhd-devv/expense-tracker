# Telegram: лише відкриття вебзастосунків

## Межі продукту

За вимогою користувача від 2026-11-04 бот показує рівно дві inline
`web_app` кнопки: «💸 Витрати» (`💸 Expenses`) на `BOT_APP_URL` і
«✅ Завдання» (`✅ Tasks`) на `BOT_APP_URL` + `/tasks`.
Кнопки відкривають відповідний Web App одразу. Reply `KeyboardButton.web_app`
не використовуй: він не передає підписаний `initData` для входу.

Будь-яке приватне повідомлення людини лише повертає меню. Нативний Telegram
Start обробляється так само, без command parser. Команд, deep-link сценаріїв,
діалогів, callback handlers, керування витратами/накопиченнями/завданнями,
AI-обробки, завантаження аудіо та сповіщень у чаті немає.
Групи, повідомлення ботів і callbacks ігноруються.

Перед меню надсилається короткий текст із `ReplyKeyboardRemove()`, щоб
прибрати меню старої версії. Потім окреме повідомлення містить дві inline
кнопки. Мова меню — `en` для Telegram `language_code`, що починається з
`en`, інакше `uk`. Бот не читає профіль; налаштування вебзастосунків
зберігаються на backend і не змінюються повідомленням у боті.

## Доставка меню

Webhook перевіряє `X-Telegram-Bot-Api-Secret-Token`, обмежує розмір запиту
і приймає лише private human messages. До inbox потрапляють `update_id`,
ID/дата повідомлення, private chat ID та мінімальний sender із мовою.
Текст, ім'я, username, audio/file IDs і callback data не зберігаються.
2xx повертається після deduplicated commit у PostgreSQL через приватний API.
Непідтримувані updates отримують 2xx без persistence.

Один inbox worker claim-ить lease, передає повідомлення aiogram dispatcher
і позначає результат. Lease — 3 хвилини, до 8 спроб, після помилки затримка
30 секунд; вичерпані спроби потребують ручного розгляду. Повтор після
невідомої відповіді Telegram може дублювати меню. Фінансових побічних дій
немає. Старі queued callbacks пропускаються й завершуються без виконання;
старі queued messages отримують лише нове меню.

Outbox worker і створення повідомлень про збереження витрати видалені.
Старі outbox записи не доставляються. `Conversation`, `DemoSeed` та
історичний `Delivery.Kind` лишаються сумісним сховищем без робочих сценаріїв;
нова міграція чи автоматичне видалення цих даних не потрібні.

## Реєстрація та перехід

`register-webhook` — окрема явна операційна дія, не startup hook.
Вона реєструє лише `message`, зберігає pending updates, видаляє command
menus для default/all-private scopes у default/uk/en та скидає додатковий
Web App menu button до Telegram default. До її виконання Telegram може
показувати раніше зареєстровані команди; handlers для них уже немає.
Персональні/довільні scopes, створені поза цим застосунком, ця дія не змінює.

Потрібен узгоджений stop-first release backend і бота: старий бот більше
не має actor API. Старі inline launch відкривають ті самі Web Apps;
старі callback кнопки не виконують операцій. Користувач надсилає будь-яке
приватне повідомлення, щоб прибрати стару reply keyboard й отримати меню.
Деталі: [security](security.md), [deployment](../docs/deployment.md),
[ADR-020](knowledge/decisions.md).
