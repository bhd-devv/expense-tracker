# Telegram-бот і Mini App UX

## Реалізація бота

Використовуй Python та aiogram 3.x. Bot handlers, filters, keyboards і
локалізовані повідомлення живуть у `src/bot/`; бізнес-сценарії й persistence —
в .NET. Дотримуйся [архітектури](architecture.md) та
[межі довіри](security.md). Telegram-виклики роби штатним `Bot` client;
не підтримуй паралельну власну обгортку Bot API або .NET Telegram-клієнт.

## Кнопки й навігація

Основне меню — постійна `ReplyKeyboardMarkup` у приватному чаті:

```text
➕ Додати витрату       📋 Витрати
📊 Звіти               🗂 Категорії
💳 Рахунки             ⚙️ Налаштування
📱 Відкрити застосунок
```

Для головної keyboard використовуй `resize_keyboard` і підтримуваний
Telegram параметр persistence. Кнопка застосунку — `web_app` із HTTPS URL
Mini App. Також можна налаштувати menu button бота для відкриття застосунку.

Усі контекстні дії — `InlineKeyboardMarkup`: вибір категорії, рахунку,
періоду, пагінація, зміна, видалення, підтвердження, «Назад», «Скасувати».
Не замінюй ними головну reply keyboard і не засмічуй головне меню списком
категорій або записів. Для старту достатньо нативної кнопки Telegram
«Почати» / «Start»; після неї всі продуктові дії доступні кнопками без
введення slash-команд. Технічна обробка `/start` підтримує запуск бота й
deep links, але не замінює меню або кнопкові сценарії.

Підписи меню вище наведено для `uk`; для `en` використовуй відповідні
локалізовані кнопки (Add expense, Expenses, Reports, Categories, Accounts,
Settings, Open app). Повідомлення, уточнення, помилки та підтвердження
також використовують мову профілю за [product.md](product.md).
Налаштування мови й теми Mini App доступні inline-кнопками.

Після зміни мови оновлюй reply keyboard. Дії визначаються стабільними
серверними ідентифікаторами, а не AI-аналізом підписів; враховуй натискання
старої reply keyboard, щоб її текст не став описом витрати. Старі inline
callbacks проходять ті самі ownership/TTL/version перевірки незалежно від мови.

## Додавання витрати

1. «Додати витрату» пропонує надіслати опис текстом або голосом. У головному
   меню звичайне повідомлення про витрату також запускає цей сценарій;
   команди й відповіді активного діалогу не стають витратами автоматично.
2. Backend створює чернетку й фіксує сьогоднішню дату. Бот показує стан
   обробки, поки OpenRouter транскрибує голос і розбирає повідомлення.
3. Сума, опис і категорія визначаються автоматично за
   [продуктовими правилами](product.md). Рахунок підставляється за
   налаштуванням або вибирається inline, якщо бракує контексту.
4. Користувач бачить результат, а для голосу також розпізнаний текст,
   і кнопки «Зберегти», «Змінити», «Скасувати». Категорію, суму й дату
   можна виправити через «Змінити»; їх не потрібно вибирати на кожному кроці.
5. При невизначеності бот просить лише потрібне уточнення. При помилці AI
   пропонує явну повторну спробу або ручне введення без збереження витрати.
6. «Зберегти» через приватний API викликає спільний backend-сценарій один
   раз на чернетку.
   Бот показує збережену витрату з діями редагування й повернення до списку.

Початковий onboarding створює налаштування користувача й допомагає додати
рахунок/категорії; не створюй кожного разу дублікати стандартних категорій.
Перший вхід із бота та Mini App має приводити до того самого стану onboarding.

## Стан діалогів і callback

- Зберігай conversation state у PostgreSQL: User, private chat, сценарій,
  поточний крок, чернетка, версія й строк дії. Не тримай його лише в RAM.
  Власник durable стану — .NET; aiogram отримує й змінює його через API.
  Не додавай прямий SQL, Redis або generic FSM storage adapter лише заради
  підключення aiogram FSM. Використовуй FSM тільки за реальної потреби
  маршрутизації, узгодивши його із серверним станом, а не як другу копію істини.
- Початковий TTL неактивної чернетки — 30 хвилин. Після завершення поясни,
  що діалог завершено, і запропонуй почати знову; нічого не зберігай автоматично.
- Серіалізуй зміни одного діалогу або використовуй optimistic concurrency.
  Враховуй повторні й несвоєчасні updates, зокрема коли користувач швидко
  натискає кнопки чи паралельно редагує витрату в Mini App.
- `callback_data` — до 64 байтів UTF-8. Використовуй коротку дію та opaque
  серверний ID; не вкладай JSON чернетки, секрети або довірений user ID.
- Callback перевіряє власника, діалог, TTL, очікуваний крок і версію.
  Старі кнопки повертають зрозуміле повідомлення, а не повторюють мутацію.
- Швидко викликай `answerCallbackQuery`, щоб зняти індикатор очікування.
  Повільна робота виконується після надійного прийняття події.
- Для видалення показуй конкретну витрату та окреме підтвердження.
  Після завершення прибирай або оновлюй застарілі inline actions.
- Кнопки «Скасувати» / «Cancel» завершують поточну чернетку без фінансової
  мутації. «Назад» / «Back» і повернення до головного меню доступні кнопками
  на кожному потрібному кроці; введення `/cancel` не є частиною сценарію.
  Вихід у головне меню має явну, послідовну поведінку щодо чернетки.
- Екрануй користувацький текст для Telegram HTML/MarkdownV2. Дотримуйся
  обмежень повідомлень і використовуй пагінацію довгих списків.

## Приймання updates

Aiogram перевіряє webhook secret і структуру update штатними засобами.
Після перевірки передає мінімальний envelope, потрібний handlers, у приватний
inbox endpoint .NET. Backend атомарно зберігає його з унікальним `update_id`;
тільки після підтвердження durable запису webhook повертає 2xx. Не використовуй
режим, що відповідає Telegram успіхом до цього кроку, зокрема стандартне
фонове приймання aiogram без окремого durable ingress.

При неможливості підтвердити надійний запис поверни non-2xx, щоб Telegram
повторив доставку. Повтор уже прийнятого update повертає 2xx без повторного
ефекту. Не зберігай зайві частини payload або URL завантаження з bot token.
Aiogram worker claim-ить updates через API й передає їх у routers; backend
зберігає lease, спроби та стан обробки. Handler отримує діалог і викликає
прикладний сценарій через приватний API, без SQL у Python.

Власне фінансова мутація має окремий idempotency key чернетки, бо два
натискання однієї кнопки можуть мати різні `update_id`. Зміна даних/діалогу,
idempotency result та outbox event фіксуються атомарно в .NET. Між Python і
.NET немає спільної транзакції: завершення inbox фіксуй лише після відомого
результату, повторне виконання не має повторювати фінансовий ефект.
Aiogram worker отримує outbox через API, надсилає локалізовані повідомлення
штатним Bot client і підтверджує доставку. Restart або невідомий результат
надсилання може дати дубль повідомлення; backend стан і витрата залишаються
єдиними. Налаштуй claim/lease так, щоб replicas не забирали одну подію одночасно.
Враховуй rate limits Telegram, `retry_after`, недоступність API та блокування
бота користувачем. Не скасовуй збережену витрату через помилку повідомлення.

## Mini App

Інтегруй Telegram SDK у client boundary, підтримай `ready`, тему за
[design.md](design.md),
safe area/viewport і Telegram BackButton там, де це відповідає навігації.
На екрані додавання доступні текстовий опис і запис голосу з дозволом
на мікрофон. Якщо запис не підтримується або дозвіл відхилено, текстове
введення залишається доступним. Транскрипція, AI-розбір і підтвердження
використовують той самий backend-сценарій, що й Telegram-бот.
Loading, auth failure, порожні списки, втрата зв'язку й помилки валідації
мають окремі зрозумілі стани. Після зміни через будь-який канал перечитуй
актуальні дані; realtime інфраструктура для MVP не обов'язкова.

Основні дії доступні з клавіатури й мають підписи для screen readers.
Під час невідомого результату збереження не показуй хибне «не збережено»
і не створюй нову операцію автоматично.
